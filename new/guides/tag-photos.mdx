The AI tools work on **one file per call** and give you the result in the answer (or, if it takes long, in a `run_id` you poll). They are the quickest way to add data to a photo you do not want to store in Wesog.

| Tool (`slug`) | Gives you |
|---|---|
| `image_tag` | Everything at once: caption, keywords, text in the image, people, colors, place... Choose what you want with `caption`, `keywords`, `ocr`, `colors`, `celebrity`. |
| `caption` | A description of the image. |
| `ocr` | The text that appears in the image. |
| `keywords` | Keywords for a photo. |
| `image_celebrity_recognition` | The public figures in the photo. |
| `video_celebrity_recognition` | The public figures in a video, with the moments they appear. |

`GET /tools` lists the tools of your plan with the fields each accepts. Each tool also has its own reference at `https://api.wesog.com/api/tools/{slug}/docs`.

## Tag a photo from its address

<CodeGroup>
```bash cURL
curl -X POST 'https://api.wesog.com/api/v1/tools/image_tag' \
  -H "X-API-Key: $WESOG_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"image_url": "https://example.com/photos/runway.jpg", "lang": "en", "caption": true, "keywords": true, "ocr": true}'
```

```python Python
import os, requests

r = requests.post(
    "https://api.wesog.com/api/v1/tools/image_tag",
    headers={"X-API-Key": os.environ["WESOG_API_KEY"]},
    json={"image_url": "https://example.com/photos/runway.jpg", "lang": "en",
          "caption": True, "keywords": True, "ocr": True},
)
r.raise_for_status()
print(r.status_code, r.json())
```

```javascript JavaScript
const r = await fetch("https://api.wesog.com/api/v1/tools/image_tag", {
  method: "POST",
  headers: { "X-API-Key": process.env.WESOG_API_KEY, "Content-Type": "application/json" },
  body: JSON.stringify({ image_url: "https://example.com/photos/runway.jpg", lang: "en", caption: true, keywords: true, ocr: true }),
});
console.log(r.status, await r.json());
```
</CodeGroup>

The address must be public. Use either `image` or `image_url`, not both.

## Tag a file from your computer

Send the file as `multipart/form-data` in the field `image`:

<CodeGroup>
```bash cURL
curl -X POST 'https://api.wesog.com/api/v1/tools/caption' \
  -H "X-API-Key: $WESOG_API_KEY" \
  -F 'image=@/path/to/photo.jpg' \
  -F 'lang=en'
```

```python Python
with open("photo.jpg", "rb") as f:
    r = requests.post("https://api.wesog.com/api/v1/tools/caption",
                      headers={"X-API-Key": os.environ["WESOG_API_KEY"]},
                      files={"image": f}, data={"lang": "en"})
print(r.json())
```

```javascript JavaScript
import { openAsBlob } from "node:fs";

const form = new FormData();
form.append("image", await openAsBlob("photo.jpg"), "photo.jpg");
form.append("lang", "en");
const r = await fetch("https://api.wesog.com/api/v1/tools/caption", {
  method: "POST",
  headers: { "X-API-Key": process.env.WESOG_API_KEY },
  body: form,
});
console.log(await r.json());
```
</CodeGroup>

## Context makes it better

`image_tag` and `caption` accept what you already know about the photo: `event`, `city`, `country` and `date` (`YYYY-MM-DD`). With them the caption names the event and the place instead of guessing.

## What each tool returns

The output is the same clear shape for every tool. Fields that are working data are not sent (face vectors, a value repeated under several names, the echo of your input).

| Tool | Main fields |
|---|---|
| `caption` | `caption`, `city`, `country`, `date`, `event`, `location`, `celebrities`, `faces_locations` |
| `ocr` | `text`, `name` |
| `keywords` | `keywords` (list) |
| `image_tag` | the ones you asked for: `caption`, `keywords`, `ocr`, `colors`, `celebrities`, `people`, `city`, `country`, `event`, `date`... plus size and orientation |
| `image_celebrity_recognition` | `celebrities`, `faces` |
| `video_celebrity_recognition` | `celebrity_recognition_timeline`, `people` |

If you used an earlier version of the output, see [Changes](/new/changes).

## Slow answers

The call waits 5 seconds by default (change it with `timeout_ms`). If the tool is not done, you get `202` and a `run_id`; poll `GET /tools/runs/{run_id}` until `status` is `succeeded`. See [Async and polling](/new/concepts/async).

## Many photos

Make one call per photo, a few at a time (respect [Limits](/new/concepts/rate-limits)). To tag a whole folder or everything you upload, use a [workflow](/new/guides/run-workflow) instead: it runs on its own as files arrive.
