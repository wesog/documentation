Cuando una llamada falla recibes siempre un cuerpo JSON con los mismos campos:

Ejemplo de una respuesta real (una ejecución que no existe). El cuerpo puede traer además un campo `detail` con la misma información: ignóralo y usa `code`.

```json
{
  "code": "not_found",
  "message": "tool_run_not_found",
  "request_id": "3afe9fee9eea306b681a8e54efdf157d"
}
```

| Campo | Para qué usarlo |
|---|---|
| `code` | Decidir qué hace tu programa. Es una palabra estable: los mensajes pueden reescribirse, los códigos no. |
| `message` | Mostrarlo a una persona o escribirlo en tu registro. |
| `request_id` | Cítalo cuando contactes con soporte: localiza tu llamada exacta. El mismo valor viaja en la cabecera de respuesta `X-Request-ID`, también en las que salen bien. |
| `errors` | Solo en `422`: los campos que hay que corregir (abajo). |

Las integraciones antiguas encuentran además `detail` (la misma información que `message`, o la lista de problemas de un `422`). Sigue leyendo `code`.

## Códigos de estado

| Estado | `code` | Qué hacer |
|---|---|---|
| `400` | `bad_request` | La petición es incorrecta; corrígela. No la reintentes igual. |
| `401` | `api_key_missing`, `api_key_invalid` | Envía una clave válida en `X-API-Key`. |
| `403` | `forbidden`, `api_key_scope_denied`, `account_deactivated` | La clave (o la organización) no puede hacer esto. |
| `404` | `not_found` | El id o la ruta no existe, o no es tuyo. |
| `409` | `conflict`, `idempotency_key_reuse`, `idempotency_key_in_use` | El recurso está en otro estado; mira [Idempotencia](/es/new/start/idempotency). |
| `413` | `payload_too_large` | El archivo supera el límite; usa las operaciones de subida grande de la [Biblioteca](/es/new/library/upload). |
| `422` | `validation_error` | Un campo es incorrecto; lee `errors`. |
| `429` | `api_key_rate_limit_reached`, `api_key_request_limit_reached`, `subscription_api_rate_limit_reached`, `subscription_api_request_limit_reached`, `subscription_search_rate_limit_reached`, `subscription_search_limit_reached`, `client_token_rate_limited` | Se alcanzó un límite; espera y reintenta. Mira [Límites y planes](/es/new/start/limits-and-plans). |
| `500` | `internal_error` | Es cosa nuestra. Reintenta; si persiste, contacta con soporte con el `request_id`. |
| `502`, `503`, `504` | `bad_gateway`, `service_unavailable`, `gateway_timeout` | Temporal. Reintenta con una espera creciente. |

## Campos que corregir (422)

```json
{
  "code": "validation_error",
  "message": "The request is not valid. See `errors` for the fields to fix.",
  "request_id": "5d1c3f7e-6f1a-4d1b-9a54-0d0c5e6b7a21",
  "errors": [
    { "field": "body.limit", "message": "Input should be a valid integer", "type": "int_parsing" }
  ]
}
```

`field` indica dónde está el problema: `body.<campo>`, `query.<nombre>` o `path.<nombre>`. El valor que enviaste nunca se devuelve.

## Reintentos

Reintenta solo `429` (tras `Retry-After` segundos), `502`, `503`, `504` y fallos de red, con una espera creciente (1 s, 2 s, 4 s...). Nunca reintentes igual un `400`, `401`, `403`, `404` o `422`. En las llamadas que crean o lanzan algo, envía una [Idempotency-Key](/es/new/start/idempotency) para que un reintento no pueda hacerlo dos veces.

<CodeGroup>
```python Python
import os, time, requests

API = "https://api-platform.wesog.com/api/v1"
HEADERS = {"X-API-Key": os.environ["WESOG_API_KEY"]}

def call(method, path, **kw):
    for attempt in range(5):
        r = requests.request(method, f"{API}{path}", headers=HEADERS, **kw)
        if r.status_code not in (429, 502, 503, 504):
            return r
        time.sleep(int(r.headers.get("Retry-After", 2 ** attempt)))
    return r

r = call("GET", "/tools")
if not r.ok:
    err = r.json()
    print(err["code"], err["message"], err["request_id"])
```

```javascript JavaScript
const API = "https://api-platform.wesog.com/api/v1";
const HEADERS = { "X-API-Key": process.env.WESOG_API_KEY };

async function call(path, options = {}) {
  let response;
  for (let attempt = 0; attempt < 5; attempt++) {
    response = await fetch(`${API}${path}`, { ...options, headers: { ...HEADERS, ...options.headers } });
    if (![429, 502, 503, 504].includes(response.status)) return response;
    const wait = Number(response.headers.get("Retry-After")) || 2 ** attempt;
    await new Promise((resolve) => setTimeout(resolve, wait * 1000));
  }
  return response;
}

const r = await call("/tools");
if (!r.ok) {
  const err = await r.json();
  console.log(err.code, err.message, err.request_id);
}
```
