La Biblioteca es un árbol de carpetas. Un archivo se identifica por su **ruta** (`relative_path`, por ejemplo `events/2026/madrid/IMG_0412.jpg`) y, una vez indexado, por su **`resource_id`**, que usan la búsqueda y los workflows.

Necesitas una clave con el scope `library` (o sin scopes).

## Subir un archivo (hasta 50 MB)

<CodeGroup>
```bash cURL
curl -X POST 'https://api.wesog.com/api/v1/storage/upload' \
  -H "X-API-Key: $WESOG_API_KEY" \
  -H 'Idempotency-Key: 6f1c2a9e-0000-4000-8000-000000000001' \
  -F 'file=@IMG_0412.jpg' \
  -F 'relative_path=events/2026/madrid/IMG_0412.jpg'
```

```python Python
import os, uuid, requests

with open("IMG_0412.jpg", "rb") as f:
    r = requests.post(
        "https://api.wesog.com/api/v1/storage/upload",
        headers={"X-API-Key": os.environ["WESOG_API_KEY"], "Idempotency-Key": str(uuid.uuid4())},
        files={"file": f},
        data={"relative_path": "events/2026/madrid/IMG_0412.jpg"},
    )
r.raise_for_status()
print(r.json())   # {"relative_path": ..., "action": "created", "resource_id": 1048223, "source_table": "storage_image"}
```

```javascript JavaScript
import { openAsBlob } from "node:fs";

const form = new FormData();
form.append("file", await openAsBlob("IMG_0412.jpg"), "IMG_0412.jpg");
form.append("relative_path", "events/2026/madrid/IMG_0412.jpg");
const r = await fetch("https://api.wesog.com/api/v1/storage/upload", {
  method: "POST",
  headers: { "X-API-Key": process.env.WESOG_API_KEY, "Idempotency-Key": crypto.randomUUID() },
  body: form,
});
console.log(await r.json());
```
</CodeGroup>

El archivo se indexa y se puede buscar en pocos minutos. Si subes a una ruta que ya existe, el archivo se **reemplaza**. Si el archivo supera el límite, recibes `413`.

## Subir un archivo grande por partes

Para archivos de más de 50 MB (vídeos):

1. `POST /storage/upload/multipart/init` con `relative_path` y `expected_size_bytes`. Recibes un `upload_id`, el tamaño de parte y una `upload_url` por parte.
2. Envía cada parte con `PUT` a su `upload_url` (el cuerpo son los bytes de esa parte).
3. `POST /storage/upload/multipart/complete` con `relative_path`, `upload_id` y `total_parts`.

Si algo falla, `POST /storage/upload/multipart/abort` descarta las partes.

```python
import requests, os

BASE = "https://api.wesog.com/api/v1"
h = {"X-API-Key": os.environ["WESOG_API_KEY"]}

init = requests.post(f"{BASE}/storage/upload/multipart/init", headers=h,
                     json={"relative_path": "events/final.mp4", "expected_size_bytes": size, "content_type": "video/mp4"}).json()
with open("final.mp4", "rb") as f:
    for part in init["parts"]:
        requests.put(part["upload_url"], data=f.read(part["size_bytes"])).raise_for_status()
requests.post(f"{BASE}/storage/upload/multipart/complete", headers=h,
              json={"relative_path": init["relative_path"], "upload_id": init["upload_id"], "total_parts": init["total_parts"]}).raise_for_status()
```

## Echar un vistazo

`GET /storage/objects?prefix=events/2026/` lista una carpeta. Añade `recursive=true` para bajar de nivel. Consulta [Paginación](/es/new/concepts/pagination).

## Carpetas, mover y copiar

| Para | Llamada |
|---|---|
| Crear una carpeta | `POST /storage/folders` `{"relative_path": "events/2027"}` |
| Renombrar o mover un archivo o carpeta | `POST /storage/rename-object` con `source_relative_path` y `destination_relative_path` (añade `"recursive": true` para una carpeta) |
| Copiar | `POST /storage/copy-object`, con los mismos campos |

Los datos de los archivos (y su búsqueda) los acompañan.

## Cambiar los datos de un archivo

`PATCH /library/tables/{source_table}/rows/{row_id}` cambia la descripción, las palabras clave, el titular, el lugar... Envía solo lo que cambia. `source_table` y `row_id` son el `source_table` y el `entity_id` de un resultado de búsqueda (o de la respuesta de la subida).

```bash
curl -X PATCH 'https://api.wesog.com/api/v1/library/tables/storage_image/rows/1048223' \
  -H "X-API-Key: $WESOG_API_KEY" -H 'Content-Type: application/json' \
  -d '{"caption": "Rafael Nadal celebrates a point during the final in Madrid.", "keyword": ["tennis", "Nadal"]}'
```

La respuesta es el archivo tal como queda. Los nombres de los campos son los que devuelve `GET` para ese archivo (por ejemplo `caption`, `headline`, `description`, `keyword`, `city`, `country`, `event`, `author`); un nombre desconocido se rechaza con `unknown_library_fields` y la lista de nombres.

## Borrar y restaurar

`POST /trash/library/resources` con `{"resource_id": 1048223}` (el `entity_id`) manda un archivo a la papelera: desaparece de la búsqueda al instante y se puede recuperar durante **30 días**.

- `GET /trash/library` lista la papelera.
- `POST /trash/library/{trash_id}/restore` devuelve el archivo a su sitio.

<Note>Editar, borrar y restaurar necesitan una clave con el **scope `library` marcado**. Una clave sin scopes («acceso completo») no puede: crea o edita la clave y marca `library`. Borrar se puede repetir sin riesgo con una `Idempotency-Key`. Vaciar la papelera del todo se hace en la aplicación.</Note>
