Cuando una llamada falla, siempre recibes un cuerpo JSON con los mismos tres campos:

```json
{
  "code": "not_found",
  "message": "Not found.",
  "request_id": "5d1c3f7e-6f1a-4d1b-9a54-0d0c5e6b7a21"
}
```

| Campo | Úsalo para |
|---|---|
| `code` | Decidir qué hacer en tu programa. Es una palabra estable; los mensajes pueden reformularse, los códigos no. |
| `message` | Mostrarlo a una persona o escribirlo en tu registro. |
| `request_id` | Indicarlo cuando contactes con el soporte: permite localizar tu llamada exacta. El mismo valor llega en la cabecera de respuesta `X-Request-ID`, también en las llamadas correctas. |

Las integraciones antiguas encuentran además `detail` (la misma información que `message`, o la lista de problemas de un `422`). Sigue leyendo `code`.

## Códigos de estado

| Estado | `code` | Qué hacer |
|---|---|---|
| `400` | `bad_request` | La petición es incorrecta; corrígela. No la reintentes sin cambiarla. |
| `401` | `api_key_missing`, `api_key_invalid` | Envía una clave válida en `X-API-Key`. |
| `403` | `forbidden`, `api_key_scope_denied` | La clave no puede hacer esto. |
| `404` | `not_found` | El id o la ruta no existe (o no es tuyo). |
| `409` | `conflict`, `idempotency_key_reuse`, `idempotency_key_in_use` | El recurso está en otro estado; consulta [Idempotencia](/es/new/concepts/idempotency). |
| `413` | `payload_too_large` | El archivo supera el límite; usa las operaciones de subida de archivos grandes. |
| `422` | `validation_error` | Un campo es incorrecto; consulta `errors`. |
| `429` | `api_key_rate_limit_reached`, `api_key_request_limit_reached`, `subscription_search_limit_reached` | Espera y reintenta; consulta [Límites](/es/new/concepts/rate-limits). |
| `5xx` | `internal_error`, `service_unavailable` | Es cosa nuestra. Reintenta con una espera creciente; si persiste, contacta con el soporte con el `request_id`. |

## Campos que corregir (422)

```json
{
  "code": "validation_error",
  "message": "The request is not valid. See `errors` for the fields to fix.",
  "request_id": "5d1c3f7e-6f1a-4d1b-9a54-0d0c5e6b7a21",
  "errors": [
    { "field": "body.limit", "message": "Input should be a valid integer", "type": "int_parsing" }
  ]
}
```

`field` indica dónde está el problema (`body.<field>`, `query.<name>`, `path.<name>`). El valor que enviaste nunca se devuelve.

## Reintentos

Reintenta solo `429` (tras `Retry-After` segundos), `502`, `503`, `504` y fallos de red, con una espera creciente (1 s, 2 s, 4 s...). En las llamadas que crean o lanzan algo, envía una [Idempotency-Key](/es/new/concepts/idempotency) para que un reintento no pueda hacerlo dos veces.

<CodeGroup>
```python Python
import os, time, requests

def call(method, url, **kw):
    for attempt in range(5):
        r = requests.request(method, url, headers={"X-API-Key": os.environ["WESOG_API_KEY"]}, **kw)
        if r.status_code not in (429, 502, 503, 504):
            return r
        time.sleep(int(r.headers.get("Retry-After", 2 ** attempt)))
    return r

r = call("GET", "https://api.wesog.com/api/v1/tools")
if not r.ok:
    err = r.json()
    print(err["code"], err["message"], err["request_id"])
```

```javascript JavaScript
async function call(url, options = {}) {
  let response;
  for (let attempt = 0; attempt < 5; attempt++) {
    response = await fetch(url, { ...options, headers: { "X-API-Key": process.env.WESOG_API_KEY, ...options.headers } });
    if (![429, 502, 503, 504].includes(response.status)) return response;
    const wait = Number(response.headers.get("Retry-After")) || 2 ** attempt;
    await new Promise((resolve) => setTimeout(resolve, wait * 1000));
  }
  return response;
}

const r = await call("https://api.wesog.com/api/v1/tools");
if (!r.ok) {
  const err = await r.json();
  console.log(err.code, err.message, err.request_id);
}
```
